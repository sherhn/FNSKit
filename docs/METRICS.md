# Метрики и события

Статистика посещений и событий — собственный Umami на `stats.sherhn.space`. Здесь описано, что и где собирается, какие отчёты в Umami под какую метрику питча заводить и что сервис не измеряет.

---

## 1. Как устроено

- **Просмотры страниц.** Скрипт Umami стоит в `<head>` у четырнадцати страниц: главная, три редактора, проверка файла, кабинет, просмотрщик TIFF, четыре инструкции, страница под запрос регистрации и два юридических документа. Его нет там, где в адресе может быть секрет или страница служебная: страницы ошибок и `link-expired` (в них показывается адрес `/s/<токен>`), `silent-check-sso`, ссылки `/s/<токен>`.
- **События.** `site/js/stats.js` даёт `window.FNSKIT_STATS.track(имя, данные)`. Если счётчик закрыт блокировщиком или не загрузился, вызов молча ничего не делает. Скрипт подключается на страницах редакторов, проверки и кабинета перед остальными скриптами.
- **Политика безопасности.** В `site/nginx.conf` домен `stats.sherhn.space` разрешён только в `script-src` и `connect-src`. Больше ничего для счётчика не открыто.
- **Что нельзя класть в события.** Имена файлов, тексты ошибок (в них бывают имена файлов), ИНН, почту, названия компаний, содержимое документов. Только числа и короткие коды. Размер файла округляется до 0,1 МБ.

## 2. События

### Редактор (`editor.js`, `cabinet-save.js`)

| Событие | Когда | Данные |
|---|---|---|
| `profile_selected` | Переключили профиль внутри редактора | `from`, `to` |
| `files_added` | Страницы добавлены в итоговый файл (в том числе из проверки) | `profile`, `files`, `pages`, `total_pages` |
| `file_rejected` | Файл не принят | `profile`, `reason`: `format`, `size`, `pages`, `duplicate`, `read` |
| `create_opened` | Открыто окно «Скачать» | `profile`, `pages` |
| `create_blocked` | Нажали «Скачать» без согласия на обработку ПДн | `profile`, `reason` |
| `file_created` | Файл собран и скачан | `profile`, `format`, `pages`, `size_mb`, `build_seconds`, `total_seconds`; для своего профиля ещё `dpi`, `color`, `compression` |
| `file_create_failed` | Сборка не удалась | `profile`, `format`, `status` (код ответа или `other`) |
| `result_viewer_opened` | После сборки TIFF открыли просмотр | — |
| `cabinet_save_clicked` | Нажали «Сохранить в кабинет» | `format` |
| `cabinet_save_login_required` | Для сохранения нужно войти | `format` |
| `cabinet_saved` | Файл лёг в кабинет | `kind`, `format`, `size_mb` |
| `cabinet_save_failed` | Сохранить не удалось | `kind`, `format`, `status` |

`total_seconds` — время от первых добавленных страниц до готового файла в рамках одной загрузки страницы; если страницы пришли из прошлого визита, поля нет. `build_seconds` — только время ответа процессора.

### Проверка готового файла (`check.js`)

| Событие | Когда | Данные |
|---|---|---|
| `check_rejected` | Файл не взят в проверку | `profile`, `reason`: `format`, `size`, `consent` |
| `check_started` | Запрос на проверку ушёл | `profile`, `format`, `size_mb` |
| `check_result` | Отчёт получен | `profile`, `status` (`success`, `warning`, `error`), `pages`, `errors`, `warnings`, `failed`, `warned` |
| `check_failed` | Проверка не удалась | `profile`, `status` |
| `check_fix_in_editor` | Из отчёта перешли в редактор | `profile`, `status`, `failed` |

`failed` и `warned` — коды проверок через запятую: `format`, `dpi`, `color`, `compression`, `size` и другие. По ним видно, что чаще всего не так с файлами.

### Кабинет (`account.js`)

| Событие | Когда | Данные |
|---|---|---|
| `register_clicked`, `login_clicked` | Нажали «Создать аккаунт» или «Войти» | — |
| `cabinet_visit` | Кабинет открыт под аккаунтом | `files`, `business` (`ip`, `ooo`, `none`), `reminders` |
| `cabinet_tab` | Открыта вкладка | `tab` |
| `document_uploaded` | Документ загружен | `kind`, `size_mb`, `dated` |
| `document_upload_failed` | Загрузка не удалась | `kind`, `status` |
| `document_downloaded`, `document_deleted` | Скачали или удалили документ | `kind` |
| `document_date_set` | Указали или убрали срок документа | `kind`, `cleared` |
| `reminders_toggled` | Переключили письма-напоминания | `enabled` |
| `share_link_created` | Создана ссылка | `kind`, `days`, `downloads` |
| `share_link_revoked` | Ссылка отозвана | `kind` |
| `package_built` | Скачан пакет документов | `preset`, `files` |
| `package_failed` | Пакет не собрался | `preset`, `status` |
| `account_action` | Начато действие с аккаунтом | `action`: `CONFIGURE_TOTP`, `UPDATE_PASSWORD`, `UPDATE_PROFILE`, `delete_account` |
| `account_action_result` | Вернулись из Keycloak | `action`, `status` |

## 3. Метрики питча и отчёты Umami

| Метрика | Что смотреть | Оговорка |
|---|---|---|
| Время работы с документами | `file_created`, свойство `total_seconds` | Umami считает среднее и сумму по числовому свойству; медиану надо брать из экспорта или API. Без замера ручного пути (интервью, хронометраж) цифра сама по себе ничего не доказывает. |
| Доля отправок с первого раза | `check_result.status` (доля `success`), доля `file_created` среди `create_opened` | Сервис не знает, принял ли файл ФНС. Это доля файлов, которые проходят проверку по требованиям, а не доля принятых отправок. «Принято ФНС» можно получить только опросом. |
| Решённые проблемы с подписью | — | Модуля подписи пока нет, событий тоже. |
| Удержание | Отчёт Retention; `cabinet_visit` | Umami не знает аккаунт: удержание считается по посетителям (по их браузеру и адресу), а не по аккаунтам, и сильно зависит от настроек вашего Umami. |

Воронки, которые стоит завести в разделе Funnels (шаг может быть страницей или событием):

1. **Редактор:** `/editor-dlya-fns` → `files_added` → `create_opened` → `file_created` → `cabinet_saved`.
2. **Проверка:** `/check` → `check_started` → `check_result` → `check_fix_in_editor` → `file_created`.
3. **Кабинет:** `register_clicked` → `cabinet_visit` → `document_uploaded` → `document_date_set` → `reminders_toggled`.

В Goals (цели) добавьте `file_created`, `cabinet_saved`, `document_uploaded`, `package_built`.

## 4. Чего здесь нет

- **Серверных метрик.** Доли ошибок, времени обработки по перцентилям, свободного места и успеха бэкапов Umami не видит. Для них нужны журналы, алерты и бэкапы; в репозитории их пока нет, их возвращают в спринте 2.
- **Точных чисел.** События уходят из браузера: блокировщики рекламы и закрытые вкладки занижают счёт. Для слайда лучше называть дату старта сбора и абсолютные цифры.
- **Идентификатора аккаунта.** В события он не попадает намеренно: данные удалённых аккаунтов стираются (152-ФЗ), а в статистике они остались бы.

---

## 5. Что обновить при изменениях

- Новое событие — строка в таблице выше и вызов `track(...)` только с числами и кодами.
- Политика ПДн (`site/privacy.html` пока заглушка): описать счётчик, что он получает (адрес страницы, источник перехода, устройство, события), срок хранения и оператора. Если ваш Umami работает без cookie (так по умолчанию), баннер согласия на них не нужен, но это стоит указать в тексте; проверьте настройки сервера.
- Если домен статистики сменится, поправить `site/nginx.conf` (`script-src`, `connect-src`) и тег в `<head>` страниц.
